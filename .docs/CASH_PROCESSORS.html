1. Overview

The Cash In Freight processor transforms raw Excel/file data into structured D365 Finance & Operations (D365FO) customer payment (Cust-Pay) journal entries for freight customer collections, down payments, and related cash-in transactions. It handles data mapping and enrichment, financial dimension parsing and validation, custody settlement filtering, invoice balancing after FX, free text invoice validation, and exchange rate calculations. Custody settlement lines are routed to a separate custody settlement flow.

  • Data mapping and enrichment
  • Financial dimension parsing and validation
  • Exchange rate calculations
  • Custody settlement filtering (separate flow)
  • Invoice balancing after FX
  • Free text invoice validation
  • Customer payment (Cust-Pay) journal creation
Key Concept Each processor is specialized for a specific service type (Trucking or Freight), ensuring accurate processing based on business requirements.

7. Processing Flow

The processing follows a three-stage pipeline:

1. Format & Enrich
→
2. Validate
→
3. Insert to D365

Stage 1: Format and Enrich (formatAndEnrichAsync)

  1. Warm up processor data (customer names)
  2. Map raw data to CashEntryRawDataModel (type Freight)
  3. Sort lines by line number
  4. Filter lines: Custody Settlement vs other (Customer Collection, down payment, etc.)
  5. Process custody settlement lines via ProcessCustodySettlementEntryCommand
  6. Build invoice map (group by UniqueId)
  7. Check invoice balanced after FX; track unbalanced IDs
  8. Build DFO lines from invoice map (2-line or multi-line logic; filter settlement lines)
  9. Update batch and voucher numbers (max 1000 lines per batch)
  10. Fetch free text invoices from D365FO for validation

Stage 2: Validate (validateAsync)

  1. For each line: attach error if source invoice is in unbalanced set
  2. Validate required dimensions per line
  3. Validate Invoice: must exist in D365FO, be unique, and be posted

Stage 3: Insert to Dynamics (insertIntoDynamicsAsync)

  1. Currently not implemented - returns resolved promise
  2. Data is prepared for manual processing or future integration

8. Batch Processing

Entries are processed in batches with the following rules:

Batch Creation Rules

  • A new batch is created when adding entries would exceed 1000 lines
  • Each batch has a unique sequential batch number (starting from 1)

Voucher Assignment

Each invoice (grouped by UniqueId) gets a unique sequential voucher number. Vouchers are assigned per invoice group.

Line Numbering

Within each batch, line numbers are sequential starting from 1. Line numbers reset when a new batch is created.

9. Custody Settlement Filtering

Lines with SafeType = 'Custody Settlement' are excluded from the main cash-in flow:

Filtering Logic
  • Raw lines are split into custody settlement lines and other lines (Customer Collection, down payment, etc.)
  • Custody settlement lines are sent to ProcessCustodySettlementEntryCommand for separate processing (no file; raw data is passed directly)
  • Only the other lines continue through the main pipeline (invoice map, DFO lines, validation)

10. Exchange Rate Calculation

Exchange rates are calculated per line/transaction date:

Monthly Exchange Rate (to EGP)

  • If currency is EGP: rate = 100 (100%)
  • Otherwise: lookup exchange rate from D365FO for the transaction date

Reporting Currency Exchange Rate (to USD)

  • If currency is USD: rate = 100 (100%)
  • Otherwise: lookup reporting rate from D365FO for the transaction date

11. Special Behaviors

Custodysettlementfiltering

Lines with SafeType 'Custody Settlement' are excluded from the main flow and sent to ProcessCustodySettlementEntryCommand for separate custody settlement processing.

Invoicegrouping

Lines are grouped by UniqueId (invoice group). Each group can have 2 lines (customer + offset) or more; settlement lines (main account 421103) are filtered out before building DFO lines.

Invoicebalancing

After FX, each invoice group must balance (debits = credits). Unbalanced invoices are tracked and validation errors are attached.

Freetextinvoicevalidation

Each output line's Invoice number is validated against D365FO free text invoices: must exist, be unique, and be posted.

Notesreceivable

Offset lines with Ledger account type and main accounts 122201, 122202, 122203, 122204, 123510 are treated as Notes Receivable; OffsetAccountType is set to Bank and PaymentMethod to NR – EGP/USD/EUR/GBP.

Invoiceformat

Invoice is normalized to 9-digit number + suffix (e.g. 000012345/INVOICE, 000012345/OF-FW). Rejected number patterns (e.g. 0, 00) are cleared. Keywords like 'نولون' map to OF-FW, 'import store' to INVOICE.

Batchprocessing

Entries are grouped by invoice. New batches are created when the batch would exceed 1000 lines. Batch and voucher numbers are sequential starting from 1.

12. Error Handling

Errors are handled at multiple levels and collected for reporting:

Validation Errors

Each line can accumulate validation errors. These errors do not stop processing but are attached to the line for reporting.

Common Validation Error Messages

Error Key Message Pattern Cause
MainAccount "Main Account is required" Missing or empty value
MainAccount "The main account {value} does not exist in the system." Value not in Chart of Accounts
CustomerDimensions "Customer is required" Missing, empty, or "000"
CustomerDimensions "The dimension {value} does not exist in the system." Value not in Customer dimension

Processing Errors

Counter Not Found If LedgerEntryBatchCounter or LedgerVoucherCounter is not found for the company/journal, processing throws an error.
Insert Not Implemented The insertIntoDynamicsAsync method currently returns a resolved promise without inserting data. Data is prepared for manual processing.
